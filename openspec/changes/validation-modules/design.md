## Context

`scripts/validate_plugin.py` (42,971 lines at `72c9166`) holds the stdlib imports, two `os.environ` assignments that keep every scenario away from the developer's real Claude and Codex CLIs, constants, about 600 top-level helpers and fixtures, 310 scenario functions, the `SCENARIOS` registry (312 entries; two functions are registered twice), the baseline checks, and the runner: `run_scenario_processes`, `run_baseline`, `run_all`, `main`. `--all` re-invokes the file per scenario.

## Facts

- F1 — Several checks read the runner's own source by path: `validate_paths` (baseline) scans it for `run_keel`/`run_install` against `ROOT` with a mutating command and for retired paths; `assertion-shape-count` counts OR-guarded `report`+`return` sites in it and finds its own body by text; `the-dependency-resolves-where-npm-put-it` reads the `compact-task-authoring` scenario's text; `the-routing-rule-reaches-the-decision` reads the `thin-native-install` scenario's text and the `BOOTSTRAP_BLOCK_BYTE_BUDGET` comment; `validation-runner` checks every `validate_*_scenario` in `globals()` is registered; `runner-skip-accounting` executes the file's source in a namespace and overrides `SCENARIOS`, `run_baseline`, and `run_scenario_processes` before calling `run_all`.
- F2 — Baseline `validate_scripts_use_stdlib` fails any import in `scripts/*.py` outside `sys.stdlib_module_names`.
- F3 — `scripts/bump_version.js` rewrites `PACKAGE_VERSION`/`PROTOCOL_VERSION` in `scripts/validate_plugin.py` and fails when it cannot find them; `version-alignment` copies a fixed file list to a scratch directory and runs the bump there.
- F4 — 174 top-level definitions read `SCENARIOS`, nearly all as the self-registration check `label in {name for name, _ in SCENARIOS}`.
- F5 — A prototype split (a tool that moves each top-level statement's text unchanged, in order) produced 591 definitions after for 591 before, every one AST-identical except `ROOT`, whose depth changes, with the registry's names and functions in the same order. Three scenarios sampled from different modules passed, and the baseline failed only on F2 and `bump_version` only on F3.
- F6 — The suite must not write into the repository it validates (`keel-validation-runner`); importing modules would write `scripts/validation/__pycache__`.

## Decisions

- D1 — Owner's decision (#409, 2026-10-21): genuinely separate modules with explicit imports of shared helpers, and a `--group` entry in the same change.
- D2 — Placement is mechanical and reproducible. Each scenario function goes to the module its registry name's group names. Each other top-level statement goes to the one module that uses it, or to `common` when more than one does, and anything `common` uses is `common` too, so no module imports another group module. The baseline checks `run_baseline` calls go to `baseline`. Statements keep their text and relative order. The split tool and its grouping rules are recorded in this change's evidence, not committed: the result is ordinary code from then on.
- D3 — `scripts/validation/registry.py` holds the one ordered registry, importing each group module. Group modules reach it as `registry.SCENARIOS` through `from validation import registry`, which resolves while the registry is still importing because only functions read it, at call time.
- D4 — `scripts/validate_plugin.py` keeps the `os.environ` assignments' effect through `common` (imported first), sets `sys.dont_write_bytecode`, puts its own directory first on `sys.path` from `__file__` (so the `runner-skip-accounting` exec, whose `sys.path[0]` is the repository root, still imports), and keeps `run_scenario_processes`, `run_baseline`, `run_all`, and `main`, so F1's namespace override still reaches them.
- D5 — The checks in F1 that read source read every module: `scripts/validate_plugin.py` and `scripts/validation/*.py`. The assertion-shape count keeps its recorded number, because the sites move without changing. A check that looked up one scenario's text finds it in whichever module defines it.
- D6 — `validate_scripts_use_stdlib` scans `scripts/*.py` and `scripts/validation/*.py` and accepts `validation` and `validation.*` besides the standard library, and nothing else.
- D7 — `--group <name> [--jobs N]` runs the registered scenarios whose function is defined in `validation.<name>`, through `run_scenario_processes`, and summarizes as `validation --group <name> passed: <n> scenarios[, <k> skipped: …]` or names the failures; it does not run the baseline. An unknown name reports the groups that exist and exits `2`, as an unknown scenario does.
- D8 — Equivalence is measured, not assumed: `npm test` on the base commit and after the split must print the same summary line (verified count and skipped names), the registry must list the same names in the same order, and every top-level definition must exist after the split with an identical AST except the ones this change edits on purpose, which are listed by name.

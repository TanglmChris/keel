## Verified facts

- F1 — Verified fact: `RESIDENT_BLOCKS[0]["required"]` (`scripts/validate_plugin.py:90-105`) is a flat list of ten plain substrings, and `validate_resident_blocks` (`:522-524`) tests each with `required not in managed_block`, emitting `missing required topic: <substring>`. The entry is named a topic and matched as prose. Basis: both bodies.
- F2 — Verified fact: `validate_resident_blocks` has exactly two callers — `run_baseline` (`:12035`) and the `skill-portability-policy` scenario (`:1008`) — so one rewording fails in two places, and one fix covers both. Basis: a repository-wide search for the function name.
- F3 — Verified fact, reproduced 2026-07-27: rewording the bootstrap's Touch sentence to add the 5.3.0 record-layer qualifier produced `Bootstrap resident block missing required topic: Touch is the write boundary` from both callers. The change that shipped preserved the literal as a substring and appended to it, which is a workaround rather than a fix. Basis: the failing run and commit `f2ae49e`.
- F4 — Verified fact: the ten entries are two kinds. Four name a command or marker whose rename should fail the check — `Keel Bootstrap`, `keel context`, `keel gate task-start`, `keel --init`. The other six are prose or terms of art — `OpenSpec artifacts and Git`, `task capsule`, `fingerprint`, `Touch is the write boundary`, `read-only report/evidence`, `native plugin`. Basis: the list.
- F5 — Verified fact: the word `Touch` and any `bound…` word appear in the managed block only inside the sentence in question, so requiring both in one line still fails when that statement is deleted. Basis: the current block text.

## Decisions

- D1 — A required entry may be a literal `str` or a compiled pattern, and the two mean different things. A **literal** is for a command, a marker, or an identifier: if the name changes, the check must fail, because the block would then be telling a reader to run something that does not exist. A **pattern** is for prose: the concepts must remain, the wording may move. The diagnostic names which kind was missing, so an author repairing the block knows whether they renamed a command or dropped a topic. Rejected: shortening the literal to `Touch`, which would pass while the boundary statement itself was deleted, since the word survives in any rewrite that mentions Touch at all. Rejected: an any-of list of accepted phrasings, which is a guess at future wordings and grows every time one is added. Basis: F1, F4.

- D2 — Convert only the entry that has demonstrably blocked work. The other nine have not, and writing nine patterns now would mean guessing which words are load-bearing in sentences nobody has needed to reword — the same speculation D1 rejects in another form. The mechanism plus the rule in D1 is the extension path, and converting the next one is a one-line change when it bites. Basis: F3, F4.

- D3 — Honest limit, recorded so it is not mistaken for a fix: relaxing the assertion does **not** unblock naming the record-layer exemption in the bootstrap. That was blocked by the 1024-byte budget, not by the assertion. A freer wording is a little shorter than `Touch is the write boundary for product files`, but the sentence that names the exemption needs roughly nineteen bytes more than the block has. Issue #15's remaining half is the budget question, which needs its own justification rather than another compression.

## Risks

- A1 — Risk: a pattern is looser than a literal, so a sentence could satisfy `Touch … bound` while stating the boundary wrongly. Mitigation: no substring check ever proved the claim was *correct* — that is review's job, and `keel-review-checklist` reads the resident text. What the check must prove is that the topic is still present, and requiring both concepts in one line does that (F5): deleting the statement removes both.
- A2 — Risk: the same-line restriction could reject a legitimate rewrite that splits the topic across two bullets. Mitigation: accepted deliberately — a boundary rule split across two bullets is worse resident text, and the block has a twelve-line budget precisely to keep statements whole. If a split ever becomes right, the pattern is one line to widen.
- A3 — Assumption: no other entry is silently relying on prose matching to catch something a topic pattern would miss. Basis: F4's split is by inspection of all ten. Resolve by: the full suite, which exercises both callers.

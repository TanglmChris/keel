## Verified facts

- F1 — Verified fact: `isConcrete` (`src/core/task-contract.js:13-20`) returns false for any text matching `/(<[^>]+>|\bTODO\b|\bTBD\b|\bplaceholder\b)/i`, with no exemption for angle brackets inside inline code spans. Basis: the function body.
- F2 — Verified fact: `requiredFieldProblems` (`src/core/task-contract.js:246`) selects the required-field set with `const compact = isConcrete(field(task, "Verify"))`, so a non-concrete `Verify` silently selects the legacy v3 list — `Owner`, `Mode`, `Covers`, `Read`, `Commands`, `Acceptance`, `Candidate Boundary`, `Stop Rules`, `Report`. No diagnostic explains the switch. Basis: the function body and the reporter's transcript in issue #7.
- F3 — Verified fact: the `plugins/keel/<plugin-dir>/plugin.json` path is computed relative to the inspected repository in two places, `bin/keel.js:1166-1196` and `pluginObservation` in `src/core/capabilities.js:39-48`. Basis: both call sites.
- F4 — Verified fact: running `keel --install --target claude` in this repository replaced the `AGENTS.md` managed block with a byte-identical copy of `assets/bootstrap/AGENTS.md`, and `npm test` then failed four scenarios — expectation-slice-gates, expectation-completion-gates, authoring-continuity, skill-portability-policy — with `scenario root AGENTS.md missing required text: Expectation alignment`. `git checkout AGENTS.md` restored 58/58. Basis: reproduced on 2026-07-27, recorded in issue #9.
- F6 — Verified fact, reproduced while authoring this change: the defect is not limited to angle brackets. `isConcrete` also matches `\bTODO\b`, `\bTBD\b`, and `\bplaceholder\b` case-insensitively, so ordinary prose *about* placeholders trips it. Task 1.1 of this change was first written with a `Verify` reading "a compact v4 task whose Verify carries a placeholder token", and `keel gate task-start` returned eleven problems — the nine expanded v3 `missing-field` entries plus `missing-boundary` and `missing-command-check` — none of which mentioned the word that caused it. The same trap applies to `Covers`, which must also be concrete, so a `Covers` reference whose target scenario name contains "Placeholder" is unreferenceable. Both were worked around by rewording, which is exactly the cost issue #7 reports. Basis: the gate output on 2026-07-27.
- F7 — Verified fact: both spellings of a `Covers` reference to a requirement whose name contains `/` fail, in different ways. With the slash kept, the reference has four segments, `specAuthority` returns `null`, and the entry is accepted as `legacy-task-reference` — `status: pass`, authority unlinked, Acceptance empty. With the slash removed, it has three segments, matches no requirement, and yields `unresolved-covers: Covers reference could not be resolved: …`, which never mentions that a requirement name contains the separator. Basis: both cases reproduced against a fixture capability on 2026-07-27.
- F5 — Verified fact: this repository is identifiable as Keel's own source by the combination of `package.json` `name` equal to `@christang/keel` and the presence of `plugins/keel/`. A consumer repository has neither. Basis: `package.json` and the directory listing.

## Decisions

- D1 — A non-concrete `Verify` produces its own diagnostic and does not silently select the v3 field set. The compact/expanded decision stays where it is, but when `Verify` is present and judged non-concrete, the returned problems lead with a dedicated code that names the matched token. Rejected: inferring the intended schema from which other fields are present, because that guesses at authority. Basis: F2 — the reporter's seven missing-field errors were all downstream of one undisclosed decision.

- D2 — Unfilled-token forms inside inline code spans are not unfilled slots. The concreteness test strips backtick-delimited spans **before** applying the token pattern, but **after** the empty/none/pending test, so a field whose entire text is one code span is not misread as empty. The exemption covers all four token forms rather than only angle brackets: F6 shows the bare keywords are equally reachable from ordinary prose, and every instance recorded there wrote the keyword as prose. Rejected: requiring the whole value to equal a single token, because a partially filled template line such as `Touch: src/<module>.js` should still be caught. Basis: F1, F6, and the reporter's case, where the angle brackets were already inside backticks.

- D6 — A `Covers` reference whose first segment names an existing capability is always treated as a spec reference, regardless of segment count. `specAuthority` returns `null` for more than three segments, and `null` means "not a spec reference", so the entry falls through to an accepted free-text `legacy-task-reference`. Verified: the reporter's correct spelling — the one that names the requirement exactly — **passes silently with empty Acceptance**, which is worse than the failure they also hit. Gating on "first segment names a capability whose spec file exists" keeps genuine free-text references working, since those do not begin with a capability name followed by the separator. Basis: F7.

- D3 — One exported predicate answers "is this Keel's own repository", and both consumers call it rather than re-deriving the test. It requires `package.json` `name` to be `@christang/keel` *and* `plugins/keel/` to exist, so a consumer who happens to vendor a `plugins/keel/` directory is not misclassified. Basis: F3 and F5.

- D4 — In a consumer repository `doctor` omits the `native plugin source` line rather than printing it as `n/a`. The check has no consumer meaning, and issue #6 reports that a status word alone did not stop the reader from treating it as a failure; the following `Keel behavioral skills` line already carries the consumer-relevant statement. Rejected: renaming it `native plugin source (dev)`, which keeps a line the consumer must learn to ignore. Basis: issue #6's report that the pair of lines cost a debugging round.

- D5 — In Keel's own repository `--install` and `--init` skip the `AGENTS.md` bootstrap write and print an explicit `skip AGENTS.md (keel source repo)`. Rejected: moving Keel's protocol text outside the managed block, which is a larger edit to the file the validation suite asserts on and would change what consumers' `--install` produces. Basis: F4 and D3.

## Risks

- A1 — Risk: stripping inline code spans in `isConcrete` also affects `Touch`, `Covers`, and every other field it guards, so a genuinely unfilled `` `<path>` `` written inside backticks would newly pass. Mitigation: the fingerprint and the Touch-path checks still reject a path that does not exist; add a negative scenario proving a bare `<path>` outside backticks is still caught.
- A2 — Assumption: no existing valid task changes its compiled fingerprint. Basis: D1 and D2 only widen what is accepted or add diagnostics; they never narrow. Resolve by: running the full suite, which includes fingerprint-stability scenarios, before completing each task.
- A3 — Risk: omitting the `native plugin source` line in consumer repositories removes a signal a maintainer may rely on when debugging someone else's project. Mitigation: the line still prints whenever the predicate matches, and `--doctor` output is not the only surface — `keel project --target <target> --json` still carries the capability detail.

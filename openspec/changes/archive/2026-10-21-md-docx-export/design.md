## Context

The #405 prototype is a directory: `md2word.py` (python-docx, lxml, Pillow), `runtime.mjs` (marked for parsing, sharp for the SVG raster fallback), `fonts-macos.conf`, `requirements.txt`, `package.json`, a shell launcher `md2word` that prefers a Codex runtime cache under `~/.cache/codex-runtimes`, a unittest file driving the launcher, a demo, and a README. Its SHA-256 sums match the ones the issue states (checked 2026-10-21 by extracting each file from the issue body).

Keel has no skill that ships executable files, no command that installs on confirmation, and a machine directory `KEEL_HOME || ~/.keel` used by chat, agents, and wake.

## Facts

- F1 — Owner decisions, 2026-10-21 (#405 comments 6309396433 and 6311576442): an on-demand skill in the keel plugin; dependencies never bundled, installed only after confirmation into a Keel-managed environment isolated from system Python and Node, never silently, never fonts or runtimes; the stdlib-only rule does not cover the converter; licences and install size recorded in the skill's docs; an existing output refused without `--replace`; `keel docx setup` lists without `--yes`, `keel docx convert` converts, the environment in `~/.keel/docx/`; no dependency installed for this change, so real conversion and the Chinese page-by-page rendering are recorded as unverified.
- F2 — Registry metadata read 2026-10-21 (no install): python-docx 1.2.0 MIT, wheel 0.25 MB; lxml 6.0.2 BSD-3-Clause, macOS universal2 cp311 wheel 8.6 MB; Pillow 12.0.0 (the newest below the prototype's `<13` bound) MIT-CMU, macOS arm64 cp311 wheel 4.65 MB; marked 17.0.5 MIT, 0.44 MB unpacked; sharp 0.35.5 Apache-2.0, 0.96 MB unpacked, plus its platform package (`@img/sharp-darwin-arm64` 0.29 MB, Apache-2.0) and libvips (`@img/sharp-libvips-darwin-arm64` 1.3.4, LGPL-3.0-or-later, 18.2 MB unpacked), which npm fetches as optional dependencies.
- F3 — Skills are mirrored byte-for-byte from `src/skills/` to `plugins/keel/skills/`, and every file under the latter ships in the npm package and the Codex plugin; no validator restricts file types in a skill, and Python under a skill is outside the stdlib-only check. `PLUGIN_SKILLS` in `scripts/validation/hosts.py` must list every plugin skill.
- F4 — `scripts/run_python.js` resolves Python 3.10 or newer (`KEEL_PYTHON` overrides); the CLI runs on Node 20.19 or newer, which is the Node the converter's helper can use.

## Decisions

- D1 — The converter files ship unchanged from the prototype under `src/skills/keel-md-docx/scripts/`: `md2word.py`, `runtime.mjs`, `fonts-macos.conf`, `requirements.txt`, `package.json`. The shell launcher is not shipped: its Codex-cache probe is a machine-specific dependency contract the issue asks not to adopt, and `keel docx convert` supplies what it supplied.
- D2 — The environment is `<KEEL_HOME or ~/.keel>/docx/`: `python/` is a virtual environment created by the Python `run_python.js` resolves, `node/` holds a copy of the pinned `package.json` and its `node_modules`, and `ready.json` is written last, naming the Keel version and the packages, so an interrupted setup reads as not set up.
- D3 — `keel docx setup` without `--yes` prints every package with its licence and size from F2, the environment path, the commands it would run, and that nothing was installed, and exits 0 having created nothing. With `--yes` it removes any `ready.json`, runs `python -m venv`, the environment's `python -m pip install -r requirements.txt`, and `npm install --prefix <env>/node --no-audit --no-fund`, then writes `ready.json`; a step that fails is named and the command exits 1 with no `ready.json`. npm is `KEEL_DOCX_NPM` or the platform npm, so a test can stand in for it.
- D4 — `keel docx convert <input.md>` defaults the output to the input with `.docx`. It refuses (exit 1, nothing written) when the input is missing, when input and output are the same file, when the template is missing, when the environment has no `ready.json` (naming `keel docx setup`), and when the output exists without `--replace` (naming `--replace`). Otherwise it runs the environment's Python on `md2word.py` with `MD2WORD_NODE` set to the running Node, `MD2WORD_NODE_MODULES` to the environment's `node_modules`, and on macOS `FONTCONFIG_FILE` to the shipped configuration unless already set, and exits with the converter's status. The converter writes to a temporary file and renames it, so a failure leaves the previous output untouched.
- D5 — The skill's description triggers on a request to export or convert Markdown containing SVG to Word or `.docx`, and its body walks the steps: run `keel docx setup` and show the plan, ask before `--yes`, state the output path, ask before `--replace`, report the converter's warnings and failures. It states the supported forms, the limits, the licences and sizes, and that real conversion and rendering are unverified on every host and platform as of this release.
- D6 — The conversion checks from the prototype's tests become the scenario `docx-converts-markdown-with-svg`, run against an environment named by `KEEL_DOCX_TEST_ENV`; without one it reports itself skipped (exit 3), because the third-party packages are an external runtime the suite does not install. It never reads the user's `~/.keel`.
- D7 — `docx` joins the mutating Keel commands, so no scenario can run it against the repository; scenarios point `KEEL_HOME` at a temporary directory.

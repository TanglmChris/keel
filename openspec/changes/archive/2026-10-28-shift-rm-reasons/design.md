## Facts

- F1 — `removeOldSessions` (`src/core/shift.js`) takes as the role's only rows whose `cwd` is a worktree bound to the role or whose transcript Keel keeps under the role. Every other skip — not the role's, no transcript, process running, copy failed, `claude rm` nonzero — is a silent `continue`, and only successes reach `entry.removed`.
- F2 — `describeHandOff` prints "old session kept, reopen it with `claude attach <id>`" whenever the handed-over session is not in `removed`.
- F3 — Measured 2026-10-28 on this machine (Claude Code 2.1.311): `claude agents --json` rows carry `cwd`, `id`, `kind`, `name`, `pid`, `sessionId`, `startedAt`, `state`, `status`, `waitingFor`, and no worktree. `~/.claude/jobs/<id>/state.json` of a session that created its worktree with `EnterWorktree` holds `worktreePath` and `worktreeBranch`, while its `cwd` stays the directory it started in: ChipSTRIDE's `783a74a0` has `cwd` the main checkout and `worktreePath` `.claude/worktrees/fix-usability-234-236-239`, the worktree its successor `fc16e6c2` runs in. A session started in an existing worktree has no `worktreePath`.
- F4 — `claude rm --help` (2.1.311): "Delete a background session and its worktree"; `--force-remove-worktree` only forces that deletion. No measured host command drops a listed session while keeping its worktree.
- F5 — The first ChipSTRIDE hand-over's old session `bbf3e74e` has no job state left, and its `EnterWorktree` worktree and branch disappeared within the hour; nothing else in that repository touched them.
- F6 — `docs/host-contract.md` records that a session started with `claude --bg -w` keeps writing its transcript in its worktree's project directory.

## Decisions

- D1 — The session the entry names (`entry.session`) is a candidate whatever its row's `cwd`. A candidate's transcript is looked for under its `cwd` and under its recorded `worktreePath`.
- D2 — Before `claude rm`, Keel reads `<CLAUDE_CONFIG_DIR or ~/.claude>/jobs/<row id>/state.json`. When `worktreePath` names an existing directory that is the entry's worktree, a worktree in `roles.json`, or the `cwd` of another listed session, the session is not removed, with the reason that its worktree is in use and `claude rm` would delete it. An unreadable or absent state file names no worktree, and removal proceeds as before.
- D3 — `removeOldSessions` returns `{ removed, notRemoved }`; each `notRemoved` item is `{ id, reason }`, one of: kept by `shift: keep_old_sessions`; process still running; Keel could not copy its transcript; worktree in use (D2); `claude rm` exited `<n>` with the first line of its stderr. When `claude agents` cannot be read, the named session is recorded with that reason. A delivered entry stores the list as `not_removed`; resume keeps using `removed` only.
- D4 — `keel shift status` prints, for the handed-over session: removed → as before; kept by `keep_old_sessions` → "old session kept (`shift: keep_old_sessions`), reopen it with `claude attach <id>`"; any other recorded reason → "old session not removed: <reason>; it stays in `claude agents`, and opening it (`claude attach <id>`) brings it back beside the new shift"; an entry from before this change with no record → "old session not removed (no reason recorded); …" in the same form.
- D5 — Not done: dropping a listed session while keeping its worktree (F4 shows no such command), and a cross-role sweep (#462 rejected it). A session left for a worktree in use goes at a later hand-over once that worktree is no longer in use.

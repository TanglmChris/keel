## Facts

- F1 — Commands are `plugins/keel/commands/*.md` (five today); `docs/commands.md` lists them and says Codex plugins carry no commands. Subcommands are modules under `src/core/` dispatched from `main()` in `bin/keel.js` (`branches.js` is the small model: `parse`, a `USAGE`, `run…` returning an exit code).
- F2 — `readStandingAuthorization` returns `declared` (the entries that reach this session's role, as written) and `scopes`, which keeps only the first scope of a repeated action; a check for one specific `issue:<owner>/<repo>` reads `declared`.
- F3 — The environment of a Claude Code session holds `CLAUDE_CODE_MESSAGING_TOKEN` and other host variables; nothing here may print the environment. `CLAUDECODE=1` marks Claude Code; no marker for Codex or OpenCode has been verified.
- F4 — `gh issue list --repo R --state all --search <words> --json number,title,state,url` returns the near-duplicates; `gh issue create --repo R --title T --body-file F` prints the new issue's URL. A tests-only stub `gh` on PATH stands in for the network, the one boundary mocked (as `stub_gh` in `shift.py` does).

## Decisions

- D1 — The target repository is `TanglmChris/keel`, read from `package.json`'s `repository` URL, not a flag: the command is feedback to Keel, and a flag would make it a general issue filer.
- D2 — Without `--create` nothing leaves the machine except the duplicate search, which only reads. The draft is written to `$TMPDIR/keel-feedback-<id>/issue.md` and printed, so the body survives a missing `gh`.
- D3 — Redaction runs on every free-text input and on collected output, in this order: private-key blocks, known token shapes (`gh[pousr]_`, `github_pat_`, `sk-`, `xox[abprs]-`, `xapp-`, `AKIA…`), `Bearer <x>`, `key=value` / `key: value` for names containing token, secret, password, passwd, api key or authorization, credentials in URLs, Slack IDs (a `U W C D G T B` letter, then 8 to 11 capitals or digits with at least one digit), e-mail addresses; then the home directory becomes `~` and the repository root `<project>`. The output reports a count per kind and never a value.
- D4 — Collected, and nothing else: Keel version, Node version, platform, host (`claude` from `CLAUDECODE`, else `unknown`, overridable by `--host`), and the `Keel context:` and `Next action:` lines of `keel context`. `--doctor` adds the redacted `keel --doctor` output on request, because it can carry paths. No project name, remote URL, role name or chat text is collected.
- D5 — Duplicate search words: the three longest distinct ASCII words of at least four characters from the summary, else the first twelve characters. The result is up to five issues, each `#n title (state) url`.
- D6 — `--create` is allowed when `declared` holds `issue:TanglmChris/keel` (with or without `@role`) or when `--confirmed` is passed; otherwise it exits 3 and prints the draft. `--confirmed` records that the user approved this draft and is the slash command's only use of it. No `--label`, `--assignee` or `--milestone` is ever passed, and no edit, comment, close or label of any issue is run by Keel.
- D7 — Exit codes: 0 draft printed or issue created; 2 usage; 3 refused for lack of authorization or confirmation; 4 `gh` missing, not logged in, or failed on `--create` (the draft is kept and the commands to run are printed).
- D8 — The slash command orders steps and decides nothing: it runs `keel feedback`, shows the draft, asks through the structured-choice surface (new issue / I will add to #n myself / cancel), and only on "new issue" runs `--create`, adding `--confirmed` unless the repository declares the authorization.

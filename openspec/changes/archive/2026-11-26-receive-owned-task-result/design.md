## Decisions
- D1 — The owner approved receiving only the result of the role's current execution. The application calls `keel chat show <todo-id> --collect --json`; there is no caller-supplied identity, text, endpoint or native ID. Persist a designated final-answer payload from the exact completed managed Codex turn. A read-only worker only emits text.
- D2 — Bind eligibility at delivery to the todo, role, socket, migration generation and owned thread. Match the recorded turn, directory, binding and live task before committing, under the same role lock as handover/migration. Pending migrations, obsolete tasks, unknown claims and prior-generation executions cannot publish. One atomic registry replacement records acceptance. Subsequent collection and show read the stored value even after the host goes away. No context, commentary or tool data can become a result.
- D3 — Results are data for the caller to verify. Collection neither runs instructions nor closes the todo. Existing direct CLI replies, existing receipts and ordinary show reads keep their contracts. Limit collection to a designated final message in a paginated exact-turn query.

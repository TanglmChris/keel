## Findings

- F1 — On 2026-09-28 `anthropics/claude-plugins-official`'s `marketplace.json` listed 314 plugins: 164 with a `url` source and 98 with `git-subdir`, all third-party ones pinned by `sha`, and none with an `npm` source. Its README sends third-party plugins to a submission form (https://clau.de/plugin-directory-submission).
- F2 — Probe on Claude Code 2.1.283 with an isolated `CLAUDE_CONFIG_DIR`: an entry `{source: url, url: https://github.com/TanglmChris/keel.git, sha: 385ea4b…}` with this repository's inline component declarations installed `keel` 5.79.0 in about 10 s. The cache held `node_modules` with `.bin/openspec` 1.13.2, and `keel openspec --version` and `keel --doctor` (`openspec: ok`) ran from it. This agrees with #164's F4: the host installs dependencies when the plugin root carries `package.json` beside a supported lockfile.
- F3 — Probe on the same host: a scratch clone with `.claude-plugin/plugin.json` at its root declaring the skills, agent, and hooks, behind a minimal entry `{source: url, url: file://…, ref: v9.9.9}`, installed as `keel` 5.79.0, taking the version from the root manifest. `claude plugin details` listed the six skills and the `SessionStart` and `PreToolUse` hooks, the same inventory the npm-sourced install shows (both report `Agents (0)` there). `claude plugin validate .claude-plugin/plugin.json` passed, with a warning that a root `CLAUDE.md` is not loaded as plugin context.
- F4 — `native-plugin-manifests` asserts the Claude entry is npm-sourced and carries the inline declarations; `version-alignment` checks the entry's `version` and `source.version`; `bump_version.js` refuses an entry that is not npm-sourced; `stage_claude_market_under_test` packs the tree with `npm pack` and installs it from `./package`.
- F5 — The release job creates the tag `v<version>` with `--target <merge sha>` after publishing, with notes cut from `keel/CHANGELOG.md`.
- F6 — The hook's `packagedCli()` recognizes the plugin by `package.json` named `@christang/keel` three levels above `plugins/keel/scripts/`. The git tree has that file, so the hook runs the tree's own CLI (F2's doctor run).

## Decisions

- D1 — **Root manifest.** `.claude-plugin/plugin.json` carries `name`, `version`, `description`, `author`, `repository`, `license`, and `keywords` equal to `plugins/keel/.claude-plugin/plugin.json`, plus `skills: ["./plugins/keel/skills/"]`, `agents: ["./plugins/keel/agents/keel-single-task-goal-claude.md"]`, and `hooks` equal to `plugins/keel/hooks/hooks.json` with each `${CLAUDE_PLUGIN_ROOT}/scripts/` resolved as `${CLAUDE_PLUGIN_ROOT}/plugins/keel/scripts/`. `plugins/keel/.claude-plugin/plugin.json` stays, because `--plugin-dir plugins/keel`, doctor, and Codex read it. #164's D1 rejected a root manifest "for no difference to the user"; the difference now is that a directory entry no one here controls must not have to restate our hooks.
- D2 — **Our entry.** `{name: keel, version: <v>, description, source: {source: url, url: "https://github.com/TanglmChris/keel.git", ref: "v<v>"}}`, with no `skills`, `agents`, or `hooks`. It pins the tag, not a commit: the file is part of the commit it would have to name. `bump_version.js` moves `version` and `source.ref`, and refuses an entry that is not git-sourced.
- D3 — **Official directory entry.** `scripts/official_entry.js <version> <sha>` prints `{name: keel, description, category: development, source: {source: url, url: "https://github.com/TanglmChris/keel.git", sha}, homepage: "https://github.com/TanglmChris/keel"}`, with the description read from the root manifest. It refuses a version that is not `X.Y.Z` or a sha that is not 40 hex characters. It reads nothing else and runs nothing. The release job appends a section headed `Official directory entry` with that JSON to `notes.md`, using the same merge sha the tag targets.
- D4 — **Install smoke.** `stage_claude_market_under_test` stages the working tree as a scratch git repository — tracked and modified files, plus a sentinel — tagged `v<version>`, and points a copy of the committed entry at it with a `file://` URL and the same `ref`. `native-plugin-marketplaces` keeps running only where the `claude` CLI is installed.
- D5 — **Migration.** An install made from the 5.79.0 npm-sourced entry must update to the git-sourced one through `claude plugin update`, and the updated install must carry OpenSpec at the shrinkwrap's version. Checked in an isolated configuration before release.

## Risks

- The host's dependency install (F2) is host behavior. If a future host stopped running it, the git install would still run Keel and its hooks, and OpenSpec would resolve to whatever is on PATH, which doctor already reports (#164 F5).
- How the official directory picks up a new release is not documented where we can read it. Each release states its entry (D3); asking for an update stays the owner's act.

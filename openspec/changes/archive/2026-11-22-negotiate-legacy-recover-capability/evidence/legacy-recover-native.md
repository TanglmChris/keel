# Legacy recovery on native Codex 0.167.2

Reproduced the production symptom from Keel #550 in an empty-auth home with private linked Git worktrees and a legacy managed record without an explicit reviewer or effective policy snapshot. Native resume/settings changed the same thread's cwd to the private main checkout. The shipped 5.231.0 request failed: `thread/resume.runtimeWorkspaceRoots requires experimentalApi capability`. The public CLI boundary regression failed with the same error.

With the capability requested for recover, that same fixture flow returns recovered on its original ID. Registry bytes, including the unknown delivery claim, stay identical. Source and target cold read the role's cwd. Restart and ID-only reopen return the role cwd and original runtime roots, workspace-write, on-request, and original user reviewer. Explicit migration then retains the original ID and all preexisting registry fields except the authorized endpoint change, appends migration audit, and refuses the unknown claim without executing it. All private hosts exited. Zero model turns or production changes.

The full 30-test CLI native-boundary and onboarding run passed. Real desktop composer A/B is a separate outstanding check. The first isolated App launch imported existing histories into its temporary home before the team could proceed. It was normally closed, and subsequent global config hashes differed with no fixture path present; causation is unverified. The second launch used empty application data, private mounts/network/D-Bus and a headless compositor. It exited before rendering because the private GNOME compositor failed initialization and the Wayland connection was refused. Both launches generated zero model or composer turns. The exact two-launch budget is exhausted. No fixture or import data was read for subsequent checks; only file counts and sanitized App log markers are reported. See https://github.com/TanglmChris/keel/issues/550 for the continuing desktop work.

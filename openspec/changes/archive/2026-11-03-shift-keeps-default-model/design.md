## Facts

- F1 — `handOver` in `src/core/shift.js` starts the new session with `spawnSync(claude, ["--bg", "-n", name, "--permission-mode", mode, SHIFT_START_TEXT(role)])`; no model argument exists on it, and the queue entry (`.git/keel-chat/shift/queue/<role>.json`) has no model field.
- F2 — Measured 2026-11-03 from `~/.claude/jobs/*/state.json` `respawnFlags` and the transcripts under `~/.claude/projects/-Users-my-home-mac-my-github-keel--claude-worktrees-keel-maint-cli/`: the keel-maint session that handed over (18ad54c1, 2.1.312) ran `claude-opus-5-5` throughout; the hand-over's session (8ea5bfc6, 2.1.316) ran `claude-sonnet-5-5` and its `respawnFlags` end in `--model sonnet`; so do the chipstride, yizhan and kaiwu-flow shifts. Every earlier keel-maint session (2.1.304 to 2.1.312, eight of them) ran `claude-opus-5-5`. The caller's model is not what the host chose.
- F3 — The owner's `~/.claude/settings.json` reads `"model": "opus"`, `"effortLevel": "xhigh"` and a `modelSettings` map with a per-model `effortLevel` (opus-5-5 `medium`, sonnet-5-5 `high`). The repository's `.claude/settings.json` names no model. `claude --help` (2.1.317) documents `--model <alias or full name>` and `--effort <level>` (`low`, `medium`, `high`, `xhigh`, `max`) and says nothing about the model a `--bg` session takes when neither is given.
- F4 — `readShiftDeclaration` (`src/core/config.js`) reads `shift: permission_mode:` and `keep_old_sessions:` and returns a `message` for a value it cannot read. The hand-over waiter's environment has no `CLAUDE*` variable (`armHandOver`), while `keel tick` runs with its own, so a reader of the Claude config directory must take `process.env.CLAUDE_CONFIG_DIR` or `~/.claude` as `shift.js` does at lines 617 and 716 so that it sees what the `claude` it starts will see.
- F5 — The existing scenario `shift-cli-self-shift` asserts `order[1][:2] == ["--bg", "-n"]`, `order[1][3:5] == ["--permission-mode", "auto"]` and the prompt as the last argument; a `--model` placed after the mode keeps all three true.

## Decisions

- D1 — The model comes from the first source naming one, in the host's own order of precedence: `shift: model:`, `ANTHROPIC_MODEL`, the worktree's `.claude/settings.local.json`, its `.claude/settings.json`, then `settings.json` in `CLAUDE_CONFIG_DIR` or `~/.claude`. A value is a non-empty string; anything else, or a file that is missing or not valid JSON, names nothing and the next source is tried. Managed policy settings are not read; that limit goes in the docs.
- D2 — `--model <model>` goes after `--permission-mode <mode>` and before the prompt (F5). When no source names a model, no `--model` is passed, so a machine with no setting behaves as it does today.
- D3 — `shift: effort:` is one of `low`, `medium`, `high`, `xhigh`, `max` and is the only source of `--effort`. Keel does not read `effortLevel` or `modelSettings`, because the host applies the per-model effort itself and reproducing that map would copy a host rule that changes (F3).
- D4 — `readShiftDeclaration` returns `model` and `effort`; an `effort` outside the five levels, or a `model` that is not a plain word (letters, digits, `.`, `-`, `_`, `:`, `[`, `]`), is dropped with a `message`, which `keel shift status` prints as it does for `permission_mode`.
- D5 — The delivered entry records `model` and `model_source` (`declared`, `ANTHROPIC_MODEL`, `project-local settings`, `project settings`, `user settings`); `keel shift status` shows them on the delivered line. A hand-off that passed nothing records neither.
- D6 — Not changed: `--resume` hand-overs (the host keeps a session's saved options, so a waker resumes with the prompt only), the desktop path, `--permission-mode`, and how a session is stopped or removed.
